## .gitlab-scripts/generate_shadow.py


- [ ] Excelファイル名が変わったり削除されたりしたときに、shadowだけ残る件の対応
    - **対応策**: `generate_shadow.py` を改修する。
        - 増分スキャン（Git利用）時：削除されたファイル（`git diff` で検出かつディスクに存在しない）に対応する `.shadow` ファイルを削除する。
        - フルスキャン時：全ての `.xlsx` と `.shadow` をリストアップし、対応する `.xlsx` が存在しない孤立した `.shadow` ファイルを削除する。
    - **課題・障壁**: 誤って必要なファイルを削除しないよう、削除対象は厳密に `.<filename>.shadow` 形式にマッチするもの及び生成元と同じディレクトリにあるものに限定する必要がある。

## .gitlab-scripts/.gitlab-ci.yml

- [x] コミットする際にコミットメッセージに元のコミット情報を付与する
    - **対応策**: `.gitlab-ci.yml` の `git commit` 実行時に、環境変数 `CI_COMMIT_SHORT_SHA` や `CI_COMMIT_TITLE` をメッセージに含める。
    - **課題・障壁**: コミットメッセージが複数行や特殊文字を含む場合のエスケープ処理に注意が必要。

- [x] 作業ブランチのコミットの都度はいらない。shadowが欲しいタイミングは特定のブランチに入るタイミングのエクセルの状態を知りたいだけなので、実行タイミングの見直し
    - **対応策**: `generate_shadow.py` 内ではなく `.gitlab-ci.yml` の `rules` セクションで制御する。`$CI_COMMIT_BRANCH == "main"` や `$CI_MERGE_REQUEST_ID` など、特定のブランチやイベントでのみジョブを実行するように設定を変更する。
    - **課題・障壁**: 「特定のブランチに入るタイミング」の正確な定義（マージリクエスト作成時か、マージ後か）を確認し、それに合わせたルール記述が必要。

- [x] pipeline動作時のログに対象コミット情報を吐かせておきたい
    - **対応策**: `before_script` または `script` ブロックの冒頭に `echo` コマンドを追加し、`CI_COMMIT_SHA`, `CI_COMMIT_MESSAGE`, `CI_COMMIT_AUTHOR` 等を出力する。
    - **課題・障壁**: 特になし。
